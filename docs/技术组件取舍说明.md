## 二、当前不需要的组件

以下组件经评估后明确不需要，不纳入近期规划：

| 组件 | 不需要的原因 |
|------|-------------|
| Elasticsearch | 产品量不大（预计 < 500），MySQL LIKE + 分类筛选已够用，搜索复杂度不高，引入后增加运维成本 |
| 消息队列（RabbitMQ/Kafka） | 询盘量不大，邮件通知已用 @Async 异步，系统复杂度低，无需 MQ 解耦 |
| AI 客服/推荐/文案/报价 | 丝网产品规格和报价需人工确认，AI 功能不能直接提升核心业务闭环，引入后增加成本和维护复杂度 |
| 复杂 CRM | 当前后台询盘管理已够用，客户量不足以支撑 CRM 系统 |
| 大数据分析系统 | 当前数据量不足以支撑大数据分析，引入后无实际业务产出 |
| 微服务 | 单体应用足够满足需求，团队规模小，微服务运维成本高 |
| GraphQL | REST API 已满足前后端交互需求，前端页面固定，无需灵活查询 |

## 三、当前阶段暂不接入的组件

以下组件当前阶段暂不接入，但未来可根据业务需要按需接入：

| 组件 | 暂不接入的原因 | 后续触发条件 |
|------|----------------|-------------|
| Redis 缓存 | 当前访问量和数据量不大，MySQL 足够 | 产品 > 1000 或 QPS > 100 或需要分布式会话 |
| OSS/COS 对象存储 | 当前本地 uploads 足够，文件量和访问量上来后再迁移 | 文件 > 10GB 或需 CDN 加速或需多节点共享 |
| CDN | 域名未确认，国内访问速度可接受 | 域名确认后上线时配置 |
| Docker | 服务器环境未确认，单体应用部署简单 | 部署时根据服务器环境决定 |
| Nginx | 属于部署阶段，服务器确定后再做 | 服务器确认后 |
| CI/CD | 属于部署阶段，服务器确定后再做 | 服务器确认后 |

## 四、引入的组件及理由

### EasyExcel

**引入版本：** 4.0.3

**引入理由：**
- 询盘导出功能需要
- 阿里开源，国内生态好
- 性能优于 Apache POI

### spring-boot-starter-mail

**引入理由：**
- 询盘邮件通知功能需要
- Spring 官方支持
- 配置简单

### vue-i18n

**引入版本：** 9.x

**引入理由：**
- B2B 网站需要中英文支持
- Vue 3 官方推荐
- Composition API 模式

### 前端 sessionStorage 缓存（V2.6.1）

**实现方式：** 自研 apiCache.ts 工具，非第三方库

**引入理由：**
- 前台页面切换时公共 GET 接口重复请求
- 不引入 Redis（访问量不大，MySQL 足够）
- 不引入后端缓存组件（前端缓存已够用）
- sessionStorage 天然支持语言隔离和 TTL
- 零依赖，不增加包体积

## 五、技术选型原则

1. **够用即可** — 不引入不必要的组件，降低复杂度
2. **运维友好** — 选择运维成本低的方案
3. **渐进式** — 先简单后复杂，按需引入
4. **社区活跃** — 选择社区活跃、文档完善的组件
5. **团队熟悉** — 选择团队熟悉的技术栈
