## 一、认证与鉴权

### 1.1 JWT 认证

- **算法：** HMAC-SHA256
- **密钥：** 通过环境变量 `JWT_SECRET` 配置，本地开发默认 `xlx-jwt-secret-key-change-in-production`
- **有效期：** 24 小时
- **存储：** 前端 `localStorage`，key 为 `admin_token`
- **拦截范围：** `/api/admin/**`（除 `/api/admin/auth/login` 外）

**关键配置（WebMvcConfig.java）：**

```java
registry.addInterceptor(authInterceptor)
        .addPathPatterns("/admin/**")
        .excludePathPatterns("/admin/auth/login");
```

### 1.2 密码存储

- 使用 MD5 加密存储（V1 简化方案）
- 生产环境建议升级为 BCrypt
- 密码验证在 AuthService 中通过数据库查询比对

### 1.3 认证流程

```
1. 前端 POST /api/admin/auth/login { username, password }
2. AuthService 查询数据库，MD5 比对密码
3. 成功 → 返回 JWT token + 用户信息
4. 前端存储 token 到 localStorage
5. 后续请求 Header 携带 Authorization: Bearer <token>
6. AuthInterceptor 校验 token 有效性
7. 无效/过期 → 返回 401
```

## 二、输入校验

### 2.1 后端 Bean Validation

**Inquiry 实体校验：**

```java
@NotBlank(message = "客户姓名不能为空")
private String name;

@Email(message = "邮箱格式不正确")
private String email;
```

**PublicController 使用 @Valid：**

```java
@PostMapping("/inquiries")
public Result<Void> submitInquiry(@Valid @RequestBody Inquiry inquiry) { ... }
```

### 2.2 询盘状态白名单

InquiryService 中硬编码 7 个有效状态值：

```java
private static final Set<String> VALID_STATUSES = Set.of(
    "new", "contacted", "quoted", "sample_confirmed",
    "order_confirmed", "closed", "invalid"
);
```

无效状态直接抛出 BusinessException。

### 2.3 前端表单校验

所有表单使用 Element Plus 的 `el-form` rules 或手写校验逻辑，包含：
- 必填字段校验
- 邮箱格式校验
- 手机号格式校验
- 文件类型和大小校验

## 三、文件上传安全

### 3.1 文件类型限制

允许的文件类型（白名单）：

| 类型 | 扩展名 |
|------|--------|
| 图片 | .jpg, .jpeg, .png, .gif, .webp |
| 文档 | .pdf, .doc, .docx, .xls, .xlsx |

禁止的类型：
- 可执行文件（.exe, .bat, .sh, .js 等）
- 脚本文件（.php, .asp, .jsp 等）

### 3.2 文件大小限制

- 单文件最大：10MB
- 超限返回 400 错误："文件大小超过限制（最大 10MB）"
- 通过 `MaxUploadSizeExceededException` 捕获

### 3.3 文件存储路径

- 按业务类型分目录：`uploads/{bizType}/yyyy/MM/`
- 文件名使用时间戳 + 随机数重命名，避免路径遍历
- 静态资源映射：`/uploads/**` → `file:./uploads/`

### 3.4 已知限制

- V1 未实现 Magic Bytes 校验（仅检查扩展名）
- 建议生产环境增加文件内容头校验（防止扩展名绕过）

## 四、跨域安全（CORS）

### 4.1 配置方式

通过环境变量 `CORS_ORIGINS` 控制：

```yaml
cors:
  allowed-origins: ${CORS_ORIGINS:http://localhost:3000,http://localhost:3001}
```

### 4.2 实现（WebMvcConfig.java）

```java
String[] origins = allowedOrigins.split(",");
registry.addMapping("/api/**")
        .allowedOriginPatterns(origins)
        .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
        .allowedHeaders("*")
        .allowCredentials(true)
        .maxAge(3600);
```

### 4.3 生产环境配置

```bash
# 设置实际域名
export CORS_ORIGINS="https://xlxcn.cn,https://www.xlxcn.cn"
```

## 五、错误处理

### 5.1 全局异常处理器

**文件：** `xlx-common/.../GlobalExceptionHandler.java`

| 异常类型 | HTTP 状态码 | 返回内容 |
|----------|-------------|----------|
| BusinessException | 400（默认） | 业务错误信息 |
| MethodArgumentNotValidException | 400 | 字段校验错误 |
| BindException | 400 | 表单绑定错误 |
| MaxUploadSizeExceededException | 400 | "文件大小超过限制" |
| Exception（兜底） | 500 | "服务器内部错误" |

### 5.2 安全原则

- 未预期的异常只返回通用错误信息，不暴露堆栈
- 详细错误信息仅记录在服务端日志（`log.error`）
- BusinessException 的 message 可返回给前端（业务层面的友好提示）

### 5.3 前端错误处理

- Axios 响应拦截器统一处理 HTTP 错误
- 401 自动跳转登录页
- 其他错误显示 `ElMessage.error` 提示

## 六、SQL 注入防护

- 使用 MyBatis Plus 参数化查询，不拼接 SQL
- 所有数据库操作通过 Mapper 接口，框架自动参数化
- Flyway 迁移脚本为静态 SQL，无动态拼接

---

## 七、XSS 防护

- 前端使用 Vue 模板默认转义（`{{ }}` 自动转义 HTML）
- 不使用 `v-html` 渲染用户输入内容
- 后端返回 JSON 格式，不返回原始 HTML

---

## 八、生产环境安全清单

| 检查项 | 操作 |
|--------|------|
| JWT 密钥 | 设置强随机 `JWT_SECRET` 环境变量 |
| CORS 来源 | 设置 `CORS_ORIGINS` 为实际域名 |
| 数据库密码 | 设置强随机 `DB_PASSWORD` 环境变量 |
| HTTPS | 配置 SSL 证书，启用 HTTPS |
| 文件上传 | 增加 Magic Bytes 校验 |
| 密码加密 | 升级为 BCrypt |
| 速率限制 | 添加 API 速率限制（Nginx 或 Spring） |
| 日志审计 | 配置日志轮转和审计日志 |
