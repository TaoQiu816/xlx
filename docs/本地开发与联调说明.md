## 一、MySQL 启动

### 1.1 创建数据库

```sql
CREATE DATABASE xlx DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 1.2 确认连接

数据库默认配置：
- 地址：`localhost:3306`
- 用户名：`root`
- 密码：`root`（可通过环境变量 `DB_PASSWORD` 覆盖）
- 数据库名：`xlx`

### 1.3 Flyway 自动迁移

后端启动时 Flyway 会自动执行 `db/migration/` 下的 SQL 脚本：
- `V1__init_schema.sql` — 创建 10 张表
- `V2__seed_data.sql` — 插入初始数据（管理员账号、产品分类、示例产品等）

首次启动无需手动建表。

**重要规则：已执行的迁移文件（V1、V2...）永远不要修改。** 修改会导致校验和不匹配，后端无法启动。需要改表结构时，创建新版本文件（如 `V3__xxx.sql`），版本号递增。

**如果遇到校验和报错（Migration checksum mismatch），修复方法：**

```sql
-- 在 MySQL 中执行，删除 Flyway 历史表，让 Flyway 重新执行所有迁移
DROP TABLE IF EXISTS xlx.flyway_schema_history;
```

然后重新启动后端即可。此操作会重新建表和插入种子数据，已有的业务数据会丢失。本地开发环境可安全执行。

## 二、后端启动（xlx-api）

### 2.1 进入目录

```bash
cd xlx-api
```

### 2.2 编译

```bash
mvn clean compile
```

### 2.3 运行测试

```bash
mvn clean test
```

预期输出：22 个测试全部通过。

### 2.4 启动应用

**方式一：Maven 插件**

```bash
mvn spring-boot:run -pl xlx-gateway
```

**方式二：IDEA**

1. 打开 `xlx-api/xlx-gateway/src/main/java/com/xlx/api/XlxApiApplication.java`
2. 右键 → Run

**方式三：打包后运行**

```bash
mvn clean package -DskipTests
java -jar xlx-gateway/target/xlx-gateway-0.0.1-SNAPSHOT.jar
```

### 2.5 环境变量（可选）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `DB_PASSWORD` | `root` | MySQL 密码 |
| `JWT_SECRET` | `xlx-jwt-secret-key-change-in-production` | JWT 签名密钥 |
| `UPLOAD_PATH` | `./uploads` | 文件上传目录 |
| `CORS_ORIGINS` | `http://localhost:3000,http://localhost:3001` | CORS 允许来源 |

### 2.6 验证

```bash
curl http://localhost:8080/api/public/categories
```

预期返回 JSON 数据（产品分类列表）。

### 4.4 默认登录账号

- 用户名：`admin`
- 密码：`admin123`

### 4.5 添加管理员

V1 无后台添加管理员功能，通过 SQL 直接操作：

```sql
-- 生成新密码的 BCrypt 哈希（以 newpass123 为例）
-- 方法：启动后端，调用登录接口观察返回的密码格式，或使用在线 BCrypt 工具

-- 插入新管理员（密码: newpass123 的 BCrypt 哈希）
INSERT INTO admin_user (username, password, nickname, role, status)
VALUES ('newadmin', '$2a$12$...', '新管理员', 'admin', 1);

-- 修改现有管理员密码
UPDATE admin_user SET password = '$2a$12$...' WHERE username = 'admin';
```

BCrypt 哈希可通过以下方式生成：
- 在线工具：https://bcrypt-generator.com/
- Java 代码：`new BCryptPasswordEncoder().encode("你的密码")`

### 4.6 API 代理

同前台，Vite 自动代理 `/api` 和 `/uploads` 到后端。

### 4.6 构建生产版本

```bash
npm run build
```

输出目录：`dist/`（Vite base: `/admin/`）

## 五、联调流程

### 5.1 完整启动顺序

```
1. 启动 MySQL（确保 localhost:3306 可用）
2. 启动后端（localhost:8080）
3. 启动前台（localhost:3000）或后台（localhost:3001）
```

### 5.2 联调验证清单

| 验证项 | 操作 | 预期 |
|--------|------|------|
| 后端健康 | `curl localhost:8080/api/public/categories` | 返回分类列表 JSON |
| 前台首页 | 浏览器访问 `localhost:3000` | 显示首页，产品数据从 API 加载 |
| 前台产品页 | 点击"产品中心" | 显示产品列表 |
| 前台询盘 | 在产品详情页提交询盘 | 提交成功或显示错误信息 |
| 后台登录 | 访问 `localhost:3001/admin/login`，输入 admin/admin123 | 登录成功，跳转 Dashboard |
| 后台产品管理 | 点击"产品管理" | 显示产品列表 |
| 后台新增产品 | 点击"新增"，填写表单，提交 | 新增成功 |
| 文件上传 | 在后台上传图片 | 上传成功，返回 URL |
| 静态文件 | 访问 `localhost:8080/uploads/...` | 可访问上传的文件 |

### 5.3 常见问题

**后端启动失败 — 数据库连接不上**
- 检查 MySQL 是否运行：`mysql -u root -p`
- 检查数据库是否存在：`SHOW DATABASES;`
- 检查 `application.yml` 中的密码配置

**前端页面空白 — API 请求 404**
- 确认后端已启动在 8080 端口
- 检查 Vite 代理配置（`vite.config.ts`）

**前端页面空白 — API 请求 401**
- 后台管理页面需要 JWT token
- 确认已登录（token 存储在 `localStorage`）

**文件上传失败**
- 检查 `uploads/` 目录是否存在且可写
- 检查文件大小是否超过 10MB
- 检查文件格式是否在允许列表内

## 六、项目结构

```
XLX/
├── xlx-api/                    # Spring Boot 后端
│   ├── xlx-common/             # 公共库（工具类、异常、实体基类）
│   ├── xlx-auth/               # 认证模块（登录、JWT）
│   ├── xlx-product/            # 产品模块（产品、分类、规格、图片）
│   ├── xlx-content/            # 内容模块（证书、工厂图片）
│   ├── xlx-inquiry/            # 询盘模块
│   ├── xlx-file/               # 文件模块（上传、管理）
│   ├── xlx-config/             # 配置模块（网站配置）
│   └── xlx-gateway/            # 网关模块（入口、配置、路由）
├── xlx-web/                    # Vue 3 前台展示
├── xlx-admin/                  # Vue 3 后台管理
├── uploads/                    # 上传文件存储
└── docs/                       # 项目文档
```
